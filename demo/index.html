zkp-browser two-browser demo

Open this URL in two separate browsers or private windows. Device 1 and Device 2 exchange JSON envelopes manually, like scanning QR codes or copying through a local pairing channel.

Demo only: the private key is stored in LocalStorage for visibility. Production apps need encrypted key storage and real QR/WebRTC transport.

How to test

  1. Open this page in two separate browsers (for example Chrome and Firefox).
  2. In Browser 1, create the identity, create sample data, and create a pairing request.
  3. Copy Browser 1's pairing request into Browser 2, then create a proof.
  4. Copy Browser 2's proof response into Browser 1 and verify Device 2.
  5. Export data in Browser 1, then paste the encrypted export into Browser 2.
  6. Decrypt and import the data in Browser 2.

Use the same passphrase in both browsers. Copy/paste simulates QR or local transport.

Per-Device Identity (v2)

This flow keeps the Ed25519 root key on Device 1 and delegates a unique Ristretto255 key to Device 2. Exchange the JSON envelopes below with copy/paste or QR, in order.

  1. Device 1 creates the root identity once.
  2. Device 2 creates its own device key and sends an enrollment request.
  3. Device 1 signs a delegation for that device key.
  4. Device 2 stores the signed delegation, then creates a challenge-bound proof.
  5. Device 1 verifies the delegation signature and the device proof.
